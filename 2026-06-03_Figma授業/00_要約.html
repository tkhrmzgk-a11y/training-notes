🏷️ワークス：タグをバリアントで切り替え

昨日作ったワークスアイテム（カード）の続き（教科書124p〜）。カードには「グラフィックデザイン」などのタグが付く。この作り方には2通りある。

① 教科書の方式（126p）

  • タグだけをコンポーネント化＆バリアント
  • カードにそのインスタンスを入れる
  • タグを他の場所でも使うならこっち

② カードに直接バリアント（今回）

  • カード自体にバリアントを3つ持たせる
  • カードを他ページでよく使うならこっち
  • 文言はテキストプロパティで変更

今回は②で作成。グラフィック／ウェブ／UIデザインの3パターンをバリアントで用意。どちらが正解でもなく、使い回し方しだい。

小ワザ＆注意
  • バリアントは下に増えていく。横並びにしたい時は大枠のコンポーネントにオートレイアウトを横付けするとスッキリ。
  • 「バリアント2」「プロジェクト1」のままだと分かりにくいので、必ずリアルな文言に変える（タグ名・プロジェクト名）。

🪆ネストされたインスタンス（新機能）

2時間目に、先生が休憩中に調べてくれたもっと効率の良い作り方。教科書が書かれた頃にはなかった、ここ1年ほどで使えるようになった機能。

仕組み タグもコンポーネント＋バリアントにし、カードもコンポーネント化。カードの中にタグのインスタンスを入れておくと、右パネルに「ネストされたインスタンス」が出てくる。

これを使うと、カードのインスタンスの外側から、中に入っているタグのバリアントを直接切り替えられる。テキストプロパティ（プロジェクト名）とネストされたタグ切り替えが、カード1つの右パネルでまとめて操作できる。

→ メリット：カードもタグも別々に使い回せて、管理が細かくできる。今日は「こういう機能がある」という紹介まで。

🔲3カラムの配置・ラッパーとコンテナ

  • カード6枚を3カラム×2列で配置。アイテム幅300・間隔64で揃える。
  • グリッドのオートレイアウトは要注意：中身が 1FR 扱いになって勝手に伸びる。横並び（フレックス）2列にした方が作りやすい（コーディングではグリッドでもOK）。
  • 画像は6枚エクスポート→塗りでアップロード（一括貼り付けは今回うまくいかず、手動で）。
  • 全体を ワークスラッパー でまとめ、さらに ワークス セクションで囲んで上下160・幅1440。ボタン（View More）も配置（136p）。
ラッパー と コンテナ の違い どちらも「囲うもの」だが、ニュアンスが違う。コンテナ＝意味のある囲い方、ラッパー＝とりあえず包む（ラップ＝包む、と同じ）。名前で役割の意図を伝える。

🎭アバウト：マスク（画像の切り抜き）

アバウトセクション（教科書138p〜）。プロフィールの丸いアイコンはマスクで作る（139p）。

マスクとは ある形の部分だけを表示して、それ以外を隠す機能。Photoshopでも多用する。「一部分だけ切り抜いて表示」または「その形以外を隠す」イメージ。

作り方

  • 200pxの円（楕円ツール）を作り、画像の上に置く
  • 円を画像の下のレイヤー（最背面）に移動 → 円と画像の2つを選択
  • プロパティパネルから「マスクとしての使用」 → マスクグループになる
  • マスクグループの中の画像を動かせば、切り抜く位置を後から調整できる
地味に便利なショートカット（レイヤー移動） ⌘ + [ ]（Ctrl+[ ]）で1段ずつ前後に移動、[ ] だけで最前面・最背面へ。

⚠️480pxは絶対指定しない

アバウトのタイトル（32 Regular）と説明文（16 Regular）。説明文のテキストボックス幅を480pxにした。ここで超重要なコーディングの注意。

480と書いてあるからといって、それを信じちゃいけない。実際にコーディングする時、この説明文（Pタグ）に width: 480px と絶対指定はしません。── A先生
なぜ固定幅にしないのか width:480px と絶対指定すると、画面幅が小さいデバイスで横スクロールが生まれる。実際は幅を指定せず、ブレイクポイントでカラム落ちさせたり、%（相対指定）で画面に合わせて折り返す。Figmaの数字はあくまで目安。

🧩CSS設計：共通クラス＋ユニーク上書き

今日いちばんの山場。サービス・ワークスのセクション余白は上下160px。でもアバウトだけ上80／下120。この「ほとんど同じ、でも1つだけ違う」をHTML/CSSでどう書くか。

答え：共通クラスで揃え、1つだけ別クラスで上書き

<section class="section-container">サービス</section>
<section class="section-container">制作実績</section>
<section class="section-about section-container">私について</section>
.section-container {      /* 共通：全セクション */
  padding: 160px 0;
  margin: 0 auto;          /* 左右の共通設定もここ */
}
.section-about {          /* アバウトだけ上書き */
  padding-top: 80px;
  padding-bottom: 120px;
}
「ユニーク」の意味＆対人間の書き方 ここでのユニーク＝「被らない・重複しない」（日常の"おもしろい"ではない）。
アバウトに section-about だけ書けばコンピュータ的には動くが、あえて section-container も併記する。こうすると人が見て「これは共通のセクションだな」「ここだけ何か上書きしてるな」と分かる。コードは対コンピュータでなく対人間（チーム）で書く。

🆔class と id の使い分け

「id と class、2つ並べる書き方とどう違う？」という質問への回答。

属性性質と使いどころ
class基本はこっちで管理。何個でも付けられて上書きしやすい
idCSSの優先度（詳細度）が強すぎて上書きしづらい＝管理が難しくなる。使うのは JSと絡める時／意図的に優先度を上げたい時／ページ内リンクなど限定的な理由がある場合

つまり、普段の見た目の管理はクラスでやるのが基本。idは特別な理由があるときだけ。

🧹仕上げ（サイズの自動調整・最終チェック）

  • フッターのインスタンスを配置。現場ではヘッダー・フッターを先に作ることも多い（が、制作順に正解はない。ラフから上から順／部品から作る、どちらもアリ）。
  • 下に余分な余白が残ったら、大枠の トップPC フレームを選んで「サイズの自動調整」（148p）→ 余分が消える。
  • 最終チェック：「範囲の色」で変な色やスタイル抜け（#000のままの黒）がないか点検し、登録したブラックスタイルを当て直す。レイヤー名・重なり順も整理。
これでポートフォリオ完成！ ヘッダー → ファーストビュー → サービス → ワークス → アバウト → フッター が揃って、猫田小春のポートフォリオサイトが完成。
