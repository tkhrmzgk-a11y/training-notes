🔁前回演習1の答え合わせ

前回の演習：入力欄に名前を入れて「表示する」ボタンを押すと、P要素に「○○さん」と表示される。半分くらいできた人がいた。

実装の手順（再掲）

  1. 要素を取得：input・button・p の3つを document.querySelector('#id') で
  2. 変数に代入：const userInput = ... のように
  3. イベントを設定：ボタンに addEventListener('click', 関数名)
  4. 処理を作成：関数の中で resultText.textContent = ... で書き換え
// 完成例（+連結バージョン）
const userInput = document.querySelector('#userInput');
const displayBtn = document.querySelector('#displayBtn');
const resultText = document.querySelector('#resultText');

const displayText = () => {
  resultText.textContent = userInput.value + 'さん';
};

displayBtn.addEventListener('click', displayText);
IDの命名のあるある 演習では #userInput（キャメル）にしているが、現場では #user-input（ケバブケース）が多い。会社によってルールはバラつくが、HTMLのIDはハイフン区切りが定番。
小ネタ：シングルクォートの意味 querySelector('#xxx') のクォートは文字列として書いている。それを JS が要素に変換してくれる、というイメージ。だから必ずクォートで囲う。

📦パラメーター＝「引数」

これまで「パラメーター」と呼んでいたものは、日本語では 「引数（ひきすう）」 と呼ぶ方が一般的。意味は同じ。

  • 第1引数＝1つ目のパラメーター（例：addEventListenerのイベント種類）
  • 第2引数＝2つ目のパラメーター（例：実行する関数）

「ひきすう」と呼ぶ方が現場感がある、と先生。

📝テンプレートリテラル（+の進化形）

文字列と変数をつなぐとき、これまでは + を使っていた。新しい書き方が テンプレートリテラル。

旧：+ で連結

'カラーコード(' + color + ')'

新：テンプレートリテラル

`カラーコード(${color})`
書き方のポイント
  • 全体をバッククォート ` で囲む（シングル/ダブルではない）
  • 変数の部分を ${変数名} と書く
  • バッククォートは Shift + @（日本語配列）/ 1の隣のチルダ（US配列）

どちらでもOKだが、世の中的にはテンプレートリテラル推奨。理由：+が多いと計算式と勘違いされやすい。

🔀条件分岐とは・if文

先生の例え：焼肉の話 財布の中に 3万円あったので今日は高級焼肉／5000円なのでチェーン店——日常で自然にやっている「条件で行動を変える」。これがプログラミングの大の得意。
条件に分けて結果を変えることを 「条件分岐」、その構文を 「if文」 と呼ぶ。

if文の構造

if (自分で決める条件) {
  // 条件に合った場合の処理
} else {
  // 条件に合わない場合の処理
}

カラーピッカーへの導入

選んだ色が真っ白なら (white)、それ以外ならカラーコード、という分岐を作る。

const changeColor = () => {
  // ① 背景色を変更（if より前に！）
  backgroundColor.style.background = colorPicker.value;

  // ② 表示テキストを条件分岐
  if (colorPicker.value == '#ffffff') {
    colorParagraph.textContent = `カラーコード(${colorPicker.value}) (white)`;
  } else {
    colorParagraph.textContent = `カラーコード(${colorPicker.value})`;
  }
};
📍 if文を書く場所のクイズ（先生） 候補は3つ：① 変数定義の後 / ② 関数の中 / ③ addEventListenerの下。
答え：② 関数の中。理由＝実行されるのが関数だから、その中身を分岐させたい。
⚠️ 順番に注意 背景色の上書きは if文の前に書く。if内でエラーが出たり処理が終わると、下のコードが実行されない可能性がある。必ず動かしたい処理は if の上に。

➗演算子（算術・比較・論理）

演算子とは？ 詰まるところ「記号のこと」。+-*/などはすべて「演算子」と呼ぶ。
（正直この呼び名を覚えなくてもコードは書けるが、勉強として知っておく）

3種類の演算子

種類使うシーン例
算術演算子計算+ - * / %（余り）
比較演算子条件を作る（if文で使う）==（同じ）!=（違う）> < >= <=
論理演算子条件を組み合わせる&&（かつ）||（または）!（〜ではない）
== の動き 5 == 5 → true（両辺が同じ）
2 == 5 → false（同じではない）
ifは true なら中身を実行、false なら else へ進む。

条件には変数も入る（受講者Bさんの質問）

「if (2 == 5)」のような固定値だけでなく、実際は変数で条件を作る。例えば：

// 入力された数値が20以上だったら（年齢確認の例）
if (ageInput.value >= 20) {
  // ページを表示
} else {
  // 別のページに飛ばす
}

条件の設計はアイデア勝負。優秀なプログラマーは経験則でうまく組み立てる。

🌳else if文（複数条件）

if文だけでは2分岐まで 普通の if/else だと 「A」と「それ以外」 の2パターンしか作れない。3つ以上の条件分岐をしたいときに else if を使う。

カラーピッカー：白/黒/その他の3分岐

if (colorPicker.value == '#ffffff') {
  colorParagraph.textContent = `カラーコード(${colorPicker.value}) (white)`;
} else if (colorPicker.value == '#000000') {
  colorParagraph.textContent = `カラーコード(${colorPicker.value}) (black)`;
} else {
  colorParagraph.textContent = `カラーコード(${colorPicker.value})`;
}

注意：書き方の細かいルール }else if(...) ではなく } else if (...) と半角スペースを入れる。詰めるとエラーになる。

将来活躍する場面（PHP / WordPress） 授業の後半で出てくるWordPress（PHP）でも else if は大活躍。
例：「トップページなら top.css を読み込む／About ページなら about.css を読み込む」のようにページ別の処理分岐を作れる。不要なCSSを読み込まずに済む＝スマートで高速。

🔮次回予告：classList とハンバーガーメニュー

授業の最後（残り40秒）に A先生から告知。明日は「クラス名の管理」を JavaScript で行い、それを使ってハンバーガーメニューの開閉（表示／非表示）を実装する。いろんなWebサイトで見るあの動きを、自分で書けるようになる。

① classList とは？（クラス名の付け外し）

classList のメソッド4種類
メソッド役割
classList.add('name')対象の要素に class名を付与する
classList.remove('name')対象の要素から class名を削除する
classList.contains('name')対象の要素に そのクラス名があるかを判別する（true/false を返す）
classList.toggle('name')あれば削除・無ければ付与の 切り替え。ハンバーガーメニューでめちゃくちゃ便利
書式は 変数.classList.メソッド('class名')。変数 ＝ document.querySelector で取った要素。

② ハンバーガーメニューを作ろう！

ポイント（先生の板書より） すでに CSS で ハンバーガー→X の変形スタイルと ナビゲーションを表示するスタイルは「記述済み」。JS でやることは クラス名を付け外しするだけ。
→ 「アイコンをクリックしたら .is-active クラスを付与／削除する」という発想。CSS は .is-active がついた時のスタイルを最初から書いておく＝JS は classList.toggle('is-active') 1行でいい。
実装イメージ（明日やる予定） 
// アイコン要素を取得
const hamburger = document.querySelector('#hamburger');

// クリックしたらクラスを付け外し
hamburger.addEventListener('click', () => {
  hamburger.classList.toggle('is-active');
});
先生のアドバイス 「いろんなWebサイトで見ると、こういう実装をやってるんだなって想像がつくと思います」——プロのサイトを見るときに「これJSで書いてるな」と気付けるようになるのが今回の到達点。
