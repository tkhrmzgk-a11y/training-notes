🪜実装の手順（4ステップ）

今日いちばん大事なのが「どういう手順で動きを実装するか」。これを掴むのに時間がかかるが、JSで何か作るときは毎回この流れ（板書参照）。

JSで「動き」を作る4ステップ
  1. JS側から対象の要素を取得してくる（例：カラーピッカー）
  2. 取得した要素を変数に代入する
  3. 代入した変数にイベントを設定する
  4. そのイベントに対して実行する処理内容を作成する

今回作るのは「カラーピッカーを選ぶと、①背景色が同じ色に変わる ②16進数のカラーコードが表示される」という動き。ユーザーのアクション（色を選ぶ）に反応する＝JSの領域。

下準備のメモ JSの読み込みはCSSの読み込みの「次」に書くことが多い（リセットCSS→共通CSS→…→JS の順）。これはルールでなく「あるある」。

🎯要素の取得（querySelector）

JSからHTMLをいじるには、まず対象の要素を取ってくる。使うのは document オブジェクト（HTMLの情報が入った箱）の querySelector メソッド。

// #colorpicker のついた要素を取得して変数に入れる
let colorPicker = document.querySelector('#colorpicker');
  • querySelector の S は大文字（注意）
  • パラメーターはCSSセレクター形式（文字列なのでクォートで囲う）
  • IDで指定するのが確実。同じタグ（input等）が複数あるとどれか分からなくなるが、IDは重複しないので一発で取れる。JSでいじるためにわざわざIDを振ることもある
⚠️ よくあるエラー：defer忘れ（実演あり） <script> に defer をつけ忘れると、要素がまだ読み込まれる前にJSが走り、取得結果が null（=何もない）になる。先生も授業中にやらかした「あるあるミス」。JSファイルの読み込みには必ず defer。

🔢値の取得（.value＝プロパティ）

要素そのものでなく、その中の「値」（カラーピッカーが持つ16進数カラーコード）が欲しいときは .value をつける。

colorPicker.value  // → '#34c759' のようなカラーコード
メソッドとプロパティの違い ドット . でつなげるのはメソッドだけではない。メソッド＝命令・指示（log、alert等）／プロパティ＝情報そのもの（value等）。.value はプロパティ。

オブジェクトの構造（キーと値）

オブジェクトデータは 「キー（項目）」と「値」のペアでできている。.value は「value というキー」を指定して、そこに入っている値を呼び出している、というイメージ。フォームで習った value属性 と同じもの。

✏️テキストの書き換え（.textContent）

画面の文字を書き換えるには、要素のテキスト部分を .textContent で指定して、新しい値を代入（=）する。

// PタグのテキストをJSから上書きする
colorParagraph.textContent = 'カラーコード';
細かく指定できる JSはとても細分化されていて、要素の「IDという属性」「タグ」「テキスト」などをピンポイントで指定できる。テキストだけを扱いたいときは .textContent。

➕文字列の連結（+）

「カラーコード：#34c759」のように、文字列と変数をつなげて表示したいときは + を使う。

'カラーコード：' + colorCode
// → 'カラーコード：#34c759'
これは足し算ではない 性質の違うデータ（文字列＋変数）をそのまま並べるとエラー。+ でつなぐと連結できる。連結した結果は文字列に統一されがち（前回の '10'+'10'='1010' と同じ理屈）。

🏷️命名規則（キャメル/スネーク/ケバブ）

変数名・クラス名・ファイル名などの名前の付け方には種類（命名規則）がある。代表的な3つ。

名前書き方主な用途
キャメルケースcolorPicker（2語目の頭を大文字）JS・PHPの変数
ケバブケースcolor-picker（ハイフン区切り）HTMLクラス名・CSS変数
スネークケースcolor_picker（アンダースコア区切り）ファイル名など

使い分けの目安：JSはキャメル／HTML・CSSはケバブ／それ以外はスネーク。命名がバラバラだと可読性が下がり、チームのルールがブレてバグの原因にもなる。

変数・関数名は「2単語以上」で JSには予約語（あらかじめ使い道が決まっている単語）があり、変数名に使えない。予約語はすべて1単語なので、名前を2単語以上にすれば予約語と被らない（例 colorCode、colorPicker）。暗記するより、2語以上にする習慣で回避するのがラク。

⚡イベントとaddEventListener

イベント＝ユーザーのアクションに対して処理を実行すること。これを設定するのが addEventListener メソッド。

colorPicker.addEventListener('click', 関数名);
//                     ① イベントの種類   ② 実行する関数
先生いわく「ここが最重要」 この addEventListener がある程度使えるようになれば、JSのカリキュラムは十分。「この半年でやりたいことのほとんどはできるようになる」。難しいと感じてもここだけは押さえたい。

パラメーターは2つ

  • ① イベントの種類（決まった値・シングルクォートで囲う）：click（クリック）／mouseover（ホバー）／load（読み込み完了）／resize（リサイズ）／input（入力）など
  • ② 実行する関数（次のセクション）

※今回のカラーピッカーは input イベントを使用（入力・選択の変化に反応）。

🛠️関数の作り方

関数＝処理内容に名前をつけたもの。呼び出すと中の処理が実行される。ハリーポッターの呪文と同じ（「ファイア」で火が出る、その「火が出る」中身を自分で書く）。

書き方は2種類

A. 別で関数を用意（おすすめ）

  • 関数を作り、addEventListenerに関数名を渡す
  • すっきり・分かりやすい

B. 無名関数（直接書く）

  • 第2引数に処理を直接書く
  • 短い処理向け（サボり的）
// A. 別で関数を用意（今の書き方＝アロー関数）
let changeColor = () => {
  // 実行する処理をここに書く
};
colorPicker.addEventListener('input', changeColor);

※ function 関数名(){} という昔からの書き方もある。参考サイトで見かけたら「古い書き方」と思えばOK。授業では新しい () => {}（アロー関数）で進める。

🌳DOM（JSがHTMLを操る仕組み）

DOM（Document Object Model）＝JSが理解するHTMLの形式。JSから見たHTMLの地図のようなもの。

ざっくり理解でOK JSだけではHTML要素を直接操作できない。DOMという仕組みを通すことで、クリックやスクロールに応じてサイトの中身を更新できるようになる。DOMはブラウザに最初から実装済みなので、自分で用意するものではない。
  • DOMツリー：HTMLを枝分かれの構造（ツリー）として捉えたもの
  • ノード：その中の最小単位。エレメントノード（要素）／テキストノード（テキスト）など
  • 頂点に document（ドキュメントオブジェクト）がある

※今は触り程度でOK。「JSがHTMLを操作するための仕組みがある」と分かれば十分。本格的に学ぶときに掘り下げる。

🎨CSSを書き換える（.style）

JSから要素のCSS（見た目）を書き換えるには 要素.style.プロパティ = 値。

// 文字サイズを変える
colorParagraph.style.fontSize = '20px';
// 背景色を、選んだカラーコードに変える
container.style.backgroundColor = colorPicker.value;
ハイフン付きはキャメルケースに JSではケバブケース（ハイフン）が使えない。CSSプロパティにハイフンがある場合はキャメルケースに変換する。
font-size → fontSize／background-color → backgroundColor
  • 値が文字のときはクォートで囲う（'20px'）。数値だけなら不要
  • この style 属性での上書きは優先度が最強（!important以外のCSSには勝つ）
これでカラーピッカー完成！ 色を選ぶ → inputイベント発火 → 関数が走り → 背景色が変わり・カラーコードが表示される。CSSだけでは作れない「動き」をJSで実現できた。
