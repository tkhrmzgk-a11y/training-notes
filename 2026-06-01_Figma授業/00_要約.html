🖼️フレーム＝親要素で囲う

この日の主役の一つが フレーム（Frame）。Figmaで枠を作るときも、要素をまとめて囲うときも、ほぼ全部このフレームを使う。先生のたとえがそのまま核心だった。

HTMLで div タグとかで囲っておくみたいなの、よくあったと思うんですね。子要素を div で親要素として囲う。あれをフィグマで視覚的に表現すると、フレームを使うイメージです。── A先生

2つの使いどころ

  • ①土台（ページの枠）：フレームツール（F）を選ぶと、右パネルにデスクトップ・スマホ・タブレットなどの画面幅の一覧が出る。ここから選んで、まずページの大枠を作る。
  • ②親要素で囲う：複数の要素をまとめて1つの枠にする。レイヤーが整理され、後で整列・余白付けがしやすくなる。
作る順番（メモ必須） 子要素から作って、親要素で囲う。 いきなり枠から作らず、画像やテキスト（子）を先に用意してから、まとめてフレーム化していく。これがFigmaでカンプを組む基本手順。

HTMLで考えるとこういう入れ子

<!-- 記事カードの例：フレームは div の入れ子と同じ構造 -->
<div class="card">          ← 外枠フレーム（親）
  <img>                   ← 子（サムネイル）
  <div class="desc">    ← 子をまとめたフレーム
    <p>タイトル</p>
    <p>本文</p>
  </div>
</div>

覚えておく操作

操作やり方
フレームを作るショートカット F → 右パネルから画面幅を選ぶ
複製するOption(Alt) を押しながらドラッグ
選択範囲をフレーム化右クリック →「選択範囲のフレーム化」（⌘+Option+G）
名前をつけるフレーム化したらすぐ名前を変える（クラス名を考える感覚）
ページ名の付け方 同じファイル内でPC用とスマホ用を分けるときは トップPC / トップSP のように区別する（レイヤー名の重複を防ぐ）。ページ自体を分ける場合は SP を付けなくてもOK。

補足 先生は途中で「ショートカットはS」と言いかけたが、すぐ「フレームは F」と訂正。正しくはF。レイヤーのアイコンが シャープ(#)型になっていればフレーム、長方形ツールだとフレームにならないので注意。

📱モバイルファースト・375px

モバイルファーストとは

スマホサイズのデザインから先に作っていくこと。今のWeb制作はPC幅とスマホ幅の2種類を作るのがスタンダードで、その出発点をスマホにする考え方。

なぜ「小さい幅」を先に考えるのか 画面が広い方は、左右に余白がつくだけで済む（広がっても困らない）。逆に狭い画面は、広めに作ると要素が収まりきらず横スクロールが生まれてしまう。だから難しい方＝小さい幅を先に考える。

375px という数字

  • 375px＝今普及しているスマホで一番小さいクラスの幅（iPhone SE 等）。Figmaのスマホ一覧にはあえて無いが、最重要キーワードとしてメモ。
  • これより狭いのはかなり古い端末（iPhone 4/4s 世代）なので、ほぼ考えなくてよい。
  • PCは 1440px で組んでおけばまず安心（それ以下のPCで見る人は少ない）。「最初は1440pxで作成でいい。最初は。」
マインドの切り替え 今の自分はユーザーではなくクリエイター（作る側）。使う人の端末がどんなものかを考慮してデザインする。「クリエイター側は横スクロールはさせない。させてはいけない！」

🆚フレーム vs グループ

2時間目の冒頭、生徒の質問から「フレームとグループの違い」を解説。結論：Webデザインのカンプを作るならほぼ100%フレーム。

グループ（あまり使わない）

  • 中身を1つのオブジェクトに「まとめる」
  • 枠を拡大すると中身も一緒に拡大縮小されてしまう
  • ロゴデザインなどには使うこともある

フレーム（こっちを使う）

  • 中身を「整列」させるための親要素
  • 枠を広げても親の幅が伸び縮みするだけ（div の width/height を決める感覚）
  • セクション・カード・ヘッダー…ほぼ全部フレーム

背景色は「長方形」で作らない

よくある間違い 背景色のために長方形（レクタングル）を敷くのはNG。囲っているフレーム自体に「塗り」を追加すると、それが背景色（background-color）になる。これが一般的な作り方。

フレーム名は英語？日本語？

これもケースバイケース。訓練校の制作では英語で統一している。理由は、最近は現場でAIにコーディングを任せる場面が多く、フレーム名をそのままクラス名にして指示できると英語の方が適切に伝わるから。分かりやすさ重視であえて日本語にする現場もある。

🎨スタイル登録（色・フォント・グリッド）

スタイル登録＝サイトで使う色・フォント・エフェクト・グリッドを事前にまとめて登録しておく機能。毎回フォントを探す手間が消え、後からの一括変更もできる。

サイトを作る前段階 Figmaを開く前に、本来は「使う色・使うフォント・使う素材」を決めるのが現場のやり方。その「決めたもの」をスタイルとして登録しておく。

フォントスタイルの登録手順

  • テキストを選択 → タイプグラフィのパネルから「スタイルを適用」アイコン → ＋（スタイルの作成）
  • 名前をつけて保存（例：Heading1）。クラス名・CSS変数のイメージで命名する
  • 登録したスタイルは再編集が可能＝適用箇所がすべて一括で変わる（解除も可能）

場所メモ このメニューは最初すごく見つけづらい。「どこにあるか」を必ずメモしておくこと。

この日いちばん大事な心構え 最初からフォントサイズや余白感を決めるのは難しくて当然。イメージが湧かないから。数十本サイトを作らないと感覚はつかめない。だから今は ① まずトップページをしっかり作る → ② そこで使ったフォントをスタイル登録する という順番でOK。これを何度も繰り返すうちに、事前に決められるようになる。

カラーの登録（注意点あり）

  • 手順はフォントとほぼ同じ。「塗り」のアイコン → 作成。
  • 「スタイル」と「バリアブル」が並んでいるが、今回は必ず「スタイル」で登録（バリアブルでやってしまいがちなので注意）。
  • 色の種類：ベースカラー／メインカラー／アクセントカラー。ただし3色だけに限る必要はなく、最低3つ以上。Webデザインの見本帳などを見てトーンを意識して決める。

エフェクト＆グリッドの登録

  • エフェクトも同じ手順で登録できる。白を登録するときは、軽くドロップシャドウをかけておくと背景に埋もれず見やすい（先生おすすめのテクニック）。
  • グリッド（ガイド線）：レイアウトの基準になるガイド。Webでは「列（カラム）」一択。
  • おすすめ初期設定：本数12・型(左右余白)120・ガター(列間)24 → 中身がちょうど 1200px（世の中で最も小さいPC幅の目安）に収まる。ただしガチガチに守る必要はない。
  • Tailwind のようなフレームワークを使うとき、このカラム数がコーディングのルールの基準になる。使わなくてもサイトは作れる。

🧩コンポーネントとインスタンス

コンポーネント（直訳＝部品）＝サイト内で繰り返し使うパーツを部品化する機能（教科書47p）。ヘッダー・フッター・ボタン・カードなど、複数ページで共通のデザインに使う。

親子の関係（教科書48p） 親コンポーネントと、その複製であるインスタンス（子）の2種類がある。
  • 親（コンポーネント）の色やサイズを変えると → インスタンスにも反映される
  • 逆に、インスタンスを編集しても → 親には反映されない

置き場所のルール

実際にカンプに配置するのはインスタンス。親コンポーネントは大元なので、「コンポーネント置き場」フレームを用意してそこにまとめておく。現場では「トップページを作る → 繰り返すパーツをコンポーネント化 → 置き場に移動 → 複製したインスタンスを配置」という流れが多い。

ボタンを作る実習

ステップ操作
1. テキスト「ボタン」と打つ（登録スタイル16px / Bold）
2. オートレイアウト化Shift+A でフレーム化（=ボタンの土台）
3. 装飾フレームに塗り・パディング（左右16/上下8）・角丸8px
4. コンポーネント化⌘+Option+K。枠が紫＆アイコンが4分割の◇型になる
5. インスタンス複製するか、左パネル「アセット」からドラッグ＆ドロップ

見分け方 レイヤーパネルで、インスタンスは中が抜けた◇型のアイコン。「レイヤーパネルから目を離さない」が先生の口ぐせ。

インスタンス側で「上書き」する

親の色を変えると全インスタンスに反映される。でも例えばボタンに「ボタン」というカタカナをそのまま並べることはない。そこでインスタンス側でテキストだけを上書き（例：「申し込む」）。

  • テキストを上書きしたインスタンスは、以後その文言だけ親に追従しなくなる（他の色・サイズは追従する）。
  • 色も同様に個別上書きできる（1つだけアクセントカラーにする等）。
  • ぐちゃぐちゃになったら右クリック →「インスタンスのリセット」で初期状態に戻る。
  • 「インスタンスの切り離し」で親子関係を解除し、ただのフレームに戻すこともできる。

🔀バリアント

コンポーネントには色・サイズの反映だけでなく、コンポーネントプロパティという機能を足せる（教科書48〜49p。旧「バリアント」は今は49pのコンポーネントプロパティに統合）。主に使うのは バリアント／テキスト／ブール値 の3つ。

バリアント＝A/Bパターンを作る

1つのコンポーネントの中に、状態違い（ホバー前・ホバー中・押せない＝ディセーブル など）のパターンを持たせる機能。インスタンス側で右パネルのトグルから切り替えられる。

作り方

  • コンポーネントを選択 → 右パネル「プロパティ」の ＋ →「バリアント」
  • バリアントの ＋ でパターンを追加（例：バリアント2＝ホバー、バリアント3＝ディセーブル）し、それぞれデザインを変える
  • 名前を分かりやすく変える：初期の「プロパティ1／バリアント2」では意味不明なので、「ボタンの状態」「ホバー」「ディセーブル」などに変更すると、他の人が見ても分かる
なぜ使う？ コンポーネントもバリアントも、極論使えなくてもカンプは作れる。でも管理・編集・一括変更といった効率（仕事の質）を考えると必ず使うことになる。逆に管理せず進めると、統一性のないデザインになりやすい。

✍️テキストプロパティ

インスタンスのテキストを右パネルから簡単に書き換えられるようにする機能（教科書49p）。地味だけど、先生いわく「個人的にすごく大事」。

手順（少し面倒なので要メモ）
  1. コンポーネントを選択 → プロパティの ＋ →「テキスト」
  2. 名前と値を入力（値＝デフォルトで入る文字。例：サンプル）
  3. 反映させたいテキストレイヤーを自分で選び、外観の「バリアブルプロパティを適用」から先ほどのテキストプロパティと紐付ける

これをやっておくと、複雑なコンポーネントでもレイヤーを深く潜らずに右パネルで一発でテキスト変更できる。中身をダブルクリックで掘っていく手間（＝検証ミスや作業時間の増加）が減る。

🔘ブール値（表示/非表示）

ブール値（Boolean）＝True / False を返すもの。Figmaではレイヤーの表示・非表示をワンクリックで切り替える機能になる（教科書49p）。

使う場面の例 商品カードの「SALE」タグのように、付けたり外したりするバッジの表示/非表示。
  • コンポーネントを選択 → プロパティの ＋ →「ブール値」→ 名前（例：セール）
  • 表示/非表示を切り替えたいレイヤーを選び、外観のアイコンからプロパティを適用
  • True＝表示／False＝非表示。インスタンスではトグル（オン/オフスイッチ）で操作できる

📐オートレイアウト

本日のラスト＆最重要（教科書50p）。余白（マージン/パディング）を自動で保持し、要素の並びも自動でレイアウトしてくれるプロパティ。Figmaでボックスモデルを実現するイメージ。ボタン・カード・グローバルナビ・テーブルなど幅広く使う。

基本 オートレイアウトはフレームの一種。ショートカット Shift+A で囲う。普通のフレームより「並べるのが得意」なフレーム、と考えればOK。

方向と間隔（=Flexboxそのもの）

FigmaCSS（Flexbox）での対応
水平に並べるflex-direction: row（横並び）
垂直に並べるflex-direction: column（縦並び）
間隔を数字で指定gap（要素間の余白＝margin）
間隔を「自動」justify-content: space-between
パディング（上下/左右）padding（内側の余白）
中の位置（中央揃え等）align-items / justify-content
 
/* オートレイアウトで作ったナビを CSS にするとこんなイメージ */
.nav {
  display: flex;                    /* 水平 */
  justify-content: space-between; /* 間隔=自動 */
  gap: 80px;                    /* 要素の間隔 */
  padding: 0 32px;               /* 左右パディング */
}

サイズの決め方：hug と fill（最重要）

hug＝コンテンツを内包（教科書52p）

  • 中身（子要素）の大きさにフレームを合わせる
  • 余分な高さ・幅をピタッと詰められる
  • CSSの width: fit-content の感覚

fill＝コンテナに合わせて拡大（教科書53p）

  • 逆に親フレームの幅に子を合わせる
  • ヘッダーを1440pxの親いっぱいに広げるときに使う
  • CSSの width: 100% の感覚

つまずきポイント 「コンテナに合わせて拡大」は、親がオートレイアウトになっていないと選べない（先生も授業中ここで一瞬詰まった）。固定幅のままだと親を伸ばしても子が広がらない。

ピンと来ない人は、オートレイアウトなしでこれを作ってみてください。めっちゃ面倒くさいです。「なるほど、面倒だな」と気づいてもらえると思います。── A先生

🏗️最終演習：ヘッダーを作る

この日学んだ全部（フレーム・コンポーネント・バリアント・テキストプロパティ・オートレイアウト）を使う総合課題。

課題の要件
  • 1440px のフレームにヘッダーをデザインする
  • ナビゲーションは トップ / 私たちについて / 店舗案内 / 商品一覧 / お問い合わせ の5つ（ロゴはダミーのテキストでOK）
  • ヘッダーはコンポーネント化し、インスタンスを トップ というフレームに配置
  • ヘッダーとナビはオートレイアウトで組む
  • ナビの文字はテキストプロパティでいつでも変更できるように
  • 現在のページが分かるよう、リンクにバリアントでアクセント（下線など）をつける

📚用語集

用語意味（このクラスでの理解）
フレーム枠を作る／要素を親要素で囲う、Figmaの中心機能。HTMLの div。ショートカット F
グループ中身を1つにまとめる。拡大すると中身も拡大。Webカンプではほぼ使わない
モバイルファーストスマホサイズから先に作る考え方
375px普及スマホで最小クラスの幅（iPhone SE等）。横スクロール回避の基準
1440pxPCデザインの基本の横幅。「最初はこれでいい」
スタイル登録色・フォント・エフェクト・グリッドを事前登録し一括管理する機能
バリアブル（CSS変数）スタイルと並ぶ登録方法。今回は使わず「スタイル」で登録するのが約束
グリッド／カラムレイアウトの基準ガイド線。Webは「列」一択。12カラムが目安
フレームワークTailwind等のコーディングルール集。カラム数が基準になる
コンポーネント／インスタンス親＝部品の大元／子＝配置する複製。親→子に反映、子→親は反映なし
コンポーネントプロパティ部品に機能を足す仕組み。バリアント/テキスト/ブール値の3つを主に使う
バリアント1部品内の状態違い（ホバー/ディセーブル/現在ページ 等）
テキストプロパティインスタンスの文字を右パネルから簡単に書き換える設定
ブール値（Boolean）True/False＝レイヤーの表示/非表示の切り替え
オートレイアウト余白と並びを自動化するフレーム。Shift+A。CSSのFlexbox
hug（コンテンツを内包）中身の大きさにフレームを合わせる。fit-content
fill（コンテナに合わせて拡大）親の幅に子を合わせる。width:100%。親がオートレイアウト必須

💬先生のことば

大事なのは、我々がデザイナー目線になること。考えるのは小さい幅の方です。── モバイルファーストの核心
最初に大体どんぐらいのフォントサイズにするか…って言われてもピンとこないじゃないですか。それは絶対しょうがない。みんな最初はそうなる。まずはトップページをしっかり作ってから、使ったフォントを登録すればいい。── スタイル登録の現実的な進め方
極論、コンポーネントが使えなくてもカンプは作れます。でも管理・編集・一括変更…効率を考えると、絶対に使っていくことになります。── 便利機能との付き合い方
ピンと来ない人は、オートレイアウトなしで作ってみてください。めっちゃ面倒くさいと気づけます。── オートレイアウトのありがたみ
