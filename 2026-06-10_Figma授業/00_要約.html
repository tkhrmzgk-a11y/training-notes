⭐今日の最重要10項目

1

丸画像はCSSで丸くする

WordPress等で更新者がFigmaを使えない前提なら、丸画像で書き出さずCSSで border-radius:50% にする。

2

FV高さは固定派が無難

ファーストビューは高さ固定がデザイン4大原則的にきれい。今回は560px（モニター実表示の5分の3）。

3

ヘッダーは3分割

将来ページ追加で「振ったメニューだけ無い」等が起きうる。ロゴ／ナビ／ボタンを分けてコンポーネント化。

4

同位置ペーストの裏技

インスタンスを別フレームにコピペする時、フレームをクリックしてからペーストすると元と同じ位置に貼り付く。

5

アイテム幅は300px

カードを300pxに収めると、最小スマホ（375px）でもブレイクポイント不要でそのまま表示できる。

6

オートレイアウト一時解除

整列だけしたい時、一旦オートレイアウト化 → ⌘+Shift+G で解除。フレームも同じ。

7

プロトタイプは便利機能

クリックでページ遷移できるカンプ。コンポーネントに設定→インスタンスに反映される。

8

ホバー＝バリアント

ホバー前/後をバリアントで2状態に作り、マウスオーバー時にディソルブで切り替え。

9

アコーディオン3点セット

バリアントで開閉状態＋ブール値で表示切替＋テキストプロパティで文言。

10

余白の付け方を統一

パディング派 vs gap派は1つに揃える。混在するとエンジニアが混乱する。

📄Aboutページの作り方

6/3で完成したトップページに続いて、仮想ページ（About / プラン / 予約）も練習で作っていく。フレームは左から右に並べるのが習慣。フレーム名は AboutPC のようにページ名＋デバイス区分。

作り方の流れ
  1. フレームから Desktop を選んでAboutPCを準備
  2. 参考サンプルを プレビュー で確認（フレームを選択→プレビューボタン）
  3. ヘッダー（インスタンス）配置 → メインビジュアル → コンテンツ繰り返し → フッター

⭕丸画像はCSSで丸くする

Aboutページの丸いプロフィール画像。「丸い素材で書き出して配置する」か、「普通のJPEG/PNGをCSSで丸くする」か。

結論：CSSで丸くする 理由は 「更新する人は誰か」。WordPressなどで運用すると、クライアント側の更新担当者がFigmaやPhotoshopを扱えない可能性が高い。CSSで border-radius:50% にしておけば、どんな画像を入れても丸くなる。
サイトを更新するのは誰だっけ、って話なんですよ。制作するのは制作会社、更新するのはクライアント側の担当者。専門知識があるとは限らない。── A先生

📐ファーストビューの高さ設計

ファーストビューの高さは 「テキスト量に応じて変わる」 vs 「固定」 の2択。先生のおすすめは固定派。デザイン4大原則の「揃える」観点で、「ここがファーストビューだ」と一目で分かるようにするため。

今回の数字：560px

  • フレームは1024px高さで作るが、実際のブラウザはアドレスバー・ブックマークバー・タブなどで100〜150px減る
  • 実表示領域 ≒ 900px と見積もる
  • FVの高さ 560px ≒ 実表示の5分の3。ヒーロー画像として丁度いい比率
注意点：文章量との両立 高さを固定する場合、FV内の文章量がはみ出ない範囲で設計する必要がある。デザイン時に「ここに何文字入れるか」を意識する。

🧩ヘッダー/フッターをコンポーネント化（3分割）

ヘッダーを 「ロゴ／ナビ／お問い合わせボタン」の3パーツに分けてそれぞれコンポーネント化。フッターも同様。

なぜ3分割するのか 将来サイトが拡張されたとき、「このページにはナビだけ無し」「ボタンだけ無し」 といったケースが発生しうる。最初から3つのパーツに分けておけば、組み替えが自由。

→ 透明ヘッダーは背景に黒を敷くと見やすい。コンポーネント置き場のヘッダーは ロックしておくと便利。

📋同じ位置にペーストする小技

トップPCで作ったヘッダーのインスタンスを、AboutPCの同じ位置に貼り付けたい時。

手順 ① 元のインスタンスをコピー（⌘+C）→ ② AboutPCのフレームをクリック → ③ ペースト（⌘+V）。
これだけで 元と完全に同じ座標に貼り付く。

📱300px幅でレスポンシブを楽にする

Aboutのプロフィールカードを並べる時、アイテム幅を300pxに収めると、後のコーディングでブレイクポイントを書かずに済む。

なぜ300pxか 最小スマホの画面幅は 375px。300pxならそこに左右余白付きで余裕で収まる。
→ ブレイクポイントを打って width を変える、% で相対指定する、といった手間が減る。コード量も減る。 
/* 300pxのカードなら、375pxスマホでも左右に37.5pxずつ余白 */
.card { width: 300px; }
/* ブレイクポイントの記述、不要！ */

✂️オートレイアウト一時解除の小技

3つのアイテムを複製・整列させたい時、隙間が1pxずれることがある。「正確に整列させたいけど、最終的にはオートレイアウトいらない」という時に。

手順 ① 整列したい要素を選択 → ② Shift+A でオートレイアウト化 → ③ 隙間がゼロになることを確認 → ④ ⌘+Shift+G（Ctrl+Shift+G）でオートレイアウト解除。
オートレイアウトもフレームの一種なので、フレーム解除と同じショートカット。

🔗プロトタイプ機能（リンク接続）

2時間目の山場。プロトタイプ＝動きがあるカンプ／実際に触れるデザイン。クリックでページが遷移したり、アニメーションが動いたりする。

プロトタイプを作るメリット エンジニア側から「どこをクリックでどう動くか」が一目で分かる。仕様伝達のロスが減る。
ただし本格的なプロトタイプ作成は時間がかかるので、現場では完全には作り込まないことが多い。

リンク接続の手順

  1. 右パネルを「デザイン」から「プロトタイプ」へ切り替え
  2. クリック対象（ナビのリンク文字など）を選択
  3. 「インタラクションの追加」を押す
  4. トリガー＝「クリック時」、アクション＝「次に移動」
  5. 移動先のフレームを選ぶ（例：TopPC、AboutPC等）

3種類のアクション

アクション用途
次に移動別ページへ遷移（リンク）
次にスクロール同じページ内のセクションへ（ページ内リンク）
リンクを開く外部URL（例：ECサイトのBASE/Shopify等）
コンポーネントに設定する利点 コンポーネントに対してプロトタイプを設定すると、インスタンスにも自動で反映される。全ページのヘッダーに一度だけリンクを設定すれば終わり。

注意点：同じページ内が必須

リンクの「次に移動」は 同じFigmaページ内のフレームしか選べない。プロトタイプ接続したい場合は、コンポーネント置き場を同じページに置く必要がある。

フローの開始地点とプレビュー

  • トップにしたいフレーム（TopPC）に対して 「フローの開始地点」を追加
  • 右上の▶ボタンでプレビュー起動 → クリックでページ遷移できる動くカンプに
  • 遷移時の動き＝「スムーズスクロール&リセット」でトップから見える状態に戻す

✨ホバーアニメーション

ボタンにマウスを乗せると色が変わる、というアニメ。バリアントで実装する。

手順
  1. ボタンのコンポーネントに バリアントを追加（Default / マウスオーバー）
  2. 「マウスオーバー」状態のデザインを変える（色を反転、影を付ける等）
  3. プロトタイプタブで トリガー＝「マウスオーバー時」
  4. アクション＝「次に変更」、移動先＝マウスオーバー状態
  5. アニメーション＝「ディゾルブ」0.3秒（スマートアニメイトでもOK）

これでインスタンスでもホバー動作が再生される。実装の本番はHTML/CSSだが、Figmaで動きを見せると話が早い。

📋アコーディオンメニューの作り方

プランページの目玉。クリックで開閉する FAQ風のメニュー。前回までに学んだ バリアント＋ブール値＋テキストプロパティ を総動員する。

背景の作り方（暗めに）

  • 背景画像を配置 → 背面にスタイルの「ブラック」を敷く（画像の透明部分を黒で埋める）
  • さらに上に黒を50%透明度で重ねると、文字が読みやすい暗めの背景に

プラス/マイナスアイコンを作る

  • 長方形ツールで横棒（マイナス）を作る
  • もう1本の横棒を90度回転させて十字（プラス）に
  • 2本をフレームで囲って「アコーディオンアイコン」と命名
  • オートレイアウトの整列を無視するため、絶対位置で配置（右から16px等）

3点セットでコンポーネント化

1. バリアント

  • Default = マイナス（開いた状態）
  • Variant 2 = プラス（閉じた状態）

2. ブール値

  • 展開コンテンツの表示/非表示を切替
  • 同じコンポーネントを「予約問い合わせ」等にも流用可能
3. テキストプロパティ タイトル文字を変えるためにテキストプロパティを設定。バリアントを作る前にテキストプロパティを紐付けると、バリアントにも自動で適用されて二度手間が減る。

📃リストスタイル（Shift+Enterの小技）

BBQプランのコース内容のような箇条書きを作る時。

リスト記号の付け方

  • テキストレイヤーを選択 → タイプグラフィの書式設定からリストスタイル → • 等を選ぶ
  • HTMLの <ul><li> 相当で、コーディング時もリスト要素として実装される

Shift+Enterの小技

通常の Enter / Shift+Enter
  • Enter：改行＋次の行にもリスト記号が付く
  • Shift+Enter：改行するがリスト記号は付かない（説明文の折返しに使える）

⚖️パディング派 vs gap派（統一が大事）

テーブル内の左右の余白を取る方法は2通り。

A. パディング派

  • 外側のオートレイアウトに左右パディングをつける
  • CSSなら padding: 0 24px;

B. gap派

  • 2つの間の余白を数字で直接指定（オートレイアウトの間隔）
  • CSSなら gap: 48px;
どちらでもOK、ただし統一すること 実装の本番ではどちらかに揃えるのが鉄則。混在するとエンジニアが混乱する。

2カラムの高さ揃え

左カラムと右カラムでテキスト量が違う時、高さが揃わない。CSSのflexなら自動で揃うはずだが、Figma段階でも見せ方を選べる：

  • 高さ固定でビヨンと伸ばす → 一番シンプル
  • 外側をオートレイアウトにして「コンテナに合わせて拡大」 → flex の挙動を再現
